### How the top‑level pieces fit together
* **`app.py`** boots the Flask server, loads the **`DialogueStateManager`**, **`HumanConversationManager`**, and the **`SessionManager`**.  All incoming Socket.IO `user_message` events are routed through the dialogue manager.
* **`agents/`** contains the pure‑Python business logic – no web‑framework code, making it reusable in other contexts.
* **`data/`** abstracts data access: the *enhanced* module adds richer customer and ticket information; the *legacy* module provides a minimal `get_order_by_id` fallback.
* **`datasets/`** holds the static FAQ JSON that the FAQ lookup functions query.
* **`static/` & `templates/`** provide the thin UI layer; the UI communicates via Socket.IO to the backend.
* **`tests/`** drive the behaviour verification and serve as living documentation of expected flows.

> **Note** – Files such as `app_refactored.py`, `setup_refactored_system.py`, and the numerous `*_COMPLETE.md` markdowns are development artefacts that record incremental work; they are not part of the runtime execution path.
